## 1. 목표와 독자

**목표**: 현재 README에는 다운로드 링크 2개뿐, 사용법 문서가 전무함. "옷장 만들기"부터 v1.0.9 신기능(WD Auto, 기믹 파라미터 초기화, PhysBone 보존)까지 사용자가 스스로 해결할 수 있는 공식 매뉴얼을 만든다.

**독자 페르소나** (쉬운 순):
1. **처음 옷장을 만드는 사람** — Booth에서 아바타와 옷을 사서 입혀본 정도. MA가 뭔지 모를 수 있음 → 시작하기 4페이지가 전담
2. **옷장은 만들어봤고 세부 설정이 필요한 사람** — 블렌드셰이프, 개별 토글, 썸네일 교체 → 튜토리얼이 전담
3. **문제가 생긴 사람** — 에러 다이얼로그, 기믹 깨짐 → 문제 해결/FAQ가 전담 (화면에 뜬 문구 그대로 검색해서 도달하는 것이 목표)

**문서가 다루는 버전**: v1.0.9 정식 기준으로 작성. v1.0.8 이하와 다른 부분(WD 체크박스→드롭다운)은 본문에 버전 뱃지로 표기.

## 3. 작성 원칙 (스타일 가이드)

MA 문서 분석에서 가져온 규칙 + 이 프로젝트 고유 규칙:

1. **[시작하기·튜토리얼]** 1페이지 = 1작업, 한 호흡에 읽히는 분량(MA 튜토리얼 기준 영문 약 800단어 상당). 길어지면 페이지를 쪼갠다.
2. **[시작하기·튜토리얼]** 단계마다 스크린샷 1장 — 텍스트 직후 배치. 글로만 설명하는 단계 금지.
3. **[시작하기·튜토리얼]** 구조 고정: ① 따라하기(행동 단위) → ② "무슨 일이 일어났나?"(원리) → ③ 심화/다음 문서 링크. 페이지 끝에 이전/다음 네비게이션(Starlight 기본 제공).
4. **[레퍼런스·문제 해결]** 은 표 중심 사전 형식 — 1·2번 원칙의 예외. 단 핵심 화면 컷은 포함.
5. **UI 문구는 Localization.json 원문 그대로 인용** — 예: 버튼은 "예"/"아니오", 라벨은 "의상 기믹 파라미터 초기화". 사용자가 화면에 보이는 문구로 사이트 검색을 해서 도달할 수 있어야 한다 (에러 메시지는 페이지 제목/앵커로도 사용).
6. **전문용어는 첫 등장 페이지에서 한 줄 풀이** + FAQ의 "용어 한 줄 사전" 링크. 대상: 블렌드셰이프(셰이프키), Expressions 메뉴, Expression Parameters, saved 파라미터, FX, 비파괴.
7. **admonition 적극 사용**: `:::tip`(편한 방법) / `:::caution`(초보자 함정) / `:::danger`(되돌리기 어려운 동작).
8. **레거시 컴포넌트(ClosetToggle/ClosetBlendshape)는 새 기능처럼 설명하지 않는다** — "구버전 업그레이드" 페이지에서 마이그레이션만 안내.
9. 인게임 화면 캡처 수단은 문서 전체에서 통일 (미결사항 ⑦).

### 5.1 Modular Auto Closet이란? (`getting-started/intro`)

**목적**: 도구 개념 + "내 경우에 쓸 수 있나" 판단 + 시작 전 체크리스트.

1. 한 줄 소개: 아바타에 입힌 여러 의상을 자동으로 VRChat 메뉴에서 갈아입을 수 있게 만들어 주는 비파괴 도구
2. Before/After — [사진: 좌측 "의상마다 수동으로 FX 레이어를 만드는 애니메이터 창" vs 우측 "우클릭 메뉴 한 번" 비교]
3. "비파괴"란? — 아바타 원본을 건드리지 않고 업로드 순간에만 합성됨. 업로드 후 컴포넌트가 사라져 보이는 것이 정상이라는 점 미리 언급 (FAQ 링크)
4. **시작 전 체크리스트** (페르소나 1 전담 — 이걸 모르면 퀵스타트에서 막힘):
   - ☑ 아바타가 프로젝트에 임포트되어 있다
   - ☑ 의상이 임포트되어 있고 아바타에 **피팅 완료** (MA Setup Outfit — MA 공식 문서 링크)
   - ☑ Modular Avatar 설치됨 (개념 한 줄 + 링크)
5. **다음에 읽을 것** (MA 인트로 패턴): 설치하기 → 5분 만에 옷장 만들기 → 새 의상 추가하기 → 의상 세부 설정

### 5.7 개별 ON/OFF 토글 만들기 (`tutorials/create-toggle`)

**목적**: 옷 전체가 아니라 안경·리본 같은 단품을 인게임에서 켜고 끄기.

1. 대상 오브젝트(옷장 안에 있어야 함) 선택 → 우클릭 `Hirami > Add Create Toggle` — [사진: 컨텍스트 메뉴에서 Add Create Toggle을 하이라이트]
2. 결과: 옷장 아래 `Toggle`(토글 루트) > `Toggle_{이름}` 생성. 토글은 **기본 켜짐(스폰 시 ON) + saved**(재접속해도 상태 유지) — [사진: 하이어라키 구조 + 생성된 오브젝트의 Inspector]
3. 인게임에서는 옷장 서브메뉴 안의 "Toggle" 서브메뉴에 나타남 — [사진: 인게임 토글 메뉴]
4. 여러 개 선택 후 실행하면 `Toggle_Group` 하나로 묶임
5. `:::caution` 모음:
   - 토글 루트 이름(AutoCloset의 "토글 루트 이름" 설정)은 **토글을 만들기 전에** 정할 것 — 나중에 바꾸면 루트가 하나 더 생김
   - 같은 오브젝트에 재실행하면 사용하지 않는 파라미터가 누적됨 (1bit씩 낭비)
   - `Toggle_Group`에 재실행하면 기존 목록이 **덮어쓰기**됨 (추가가 아님)
   - 토글 루트는 **항상 옷장의 마지막 자식**으로 유지할 것 (미결사항 ④에 따라 문구 확정)
6. 블렌드셰이프를 토글에 연동하려면: 함께 생성된 BlendshapeToggle 사용 — "켜짐" = 토글 ON일 때 값 적용, "꺼짐" = 토글 OFF일 때 값 적용 — [사진: BlendshapeToggle Inspector 3줄 레이아웃]

| Inspector에 "아바타 오브젝트 내부에 배치해 주세요." | 옷장이 아바타 밖 → 아바타 안으로 이동 |
| "선택한 오브젝트의 부모에 Closet 오브젝트가 없습니다." / "AutoCloset 컴포넌트가 붙어있는 옷장 루트를 찾을 수 없습니다." | Add Create Toggle을 옷장 밖 오브젝트에 실행 → 옷장 안 오브젝트에서 실행 |
| "Closet 오브젝트에 ModularAvatarParameters가 없거나 파라미터가 없습니다." / "Closet 오브젝트에서 올바른 파라미터를 찾을 수 없습니다." | 옷장 루트의 MA Parameters가 삭제·변형됨 → Clear 후 Auto Apply Closet 재실행 |
| 콘솔에 "해당 옷장에는 자식 오브젝트가 없습니다." | 옷장에 의상이 없음 → 의상을 자식으로 추가 |
| 옷을 갈아입으면 의상 기믹이 이상한 상태로 시작 | "의상 기믹 파라미터 초기화" 꺼짐/구버전 → 켜기 (v1.0.9+) |
| 옷 전환 시 치마/머리 물리가 튐 | ① v1.0.9 미만 → 업데이트 ② v1.0.9여도 PhysBone이 비활성이거나 체인 중간 오브젝트가 꺼져 있으면 보존 제외 (직접 꺼둔 서브트리는 의도 존중으로 제외됨) → PhysBone과 경로상 오브젝트 활성 확인 |
| 의상을 드래그했는데 다이얼로그가 안 뜸 | ① 이전에 "아니오" 선택 → 밖으로 뺐다 다시 드래그 ② 의상 루트에 제작사 MA Menu Item이 이미 있음 (미결사항 ⑬) |
| 두 의상이 동시에 켜짐 | 의상 이름 중복 → 이름을 다르게 |
| 빌드하면 콘솔에 로그가 잔뜩 | 정상 동작 (경로 리매핑 정보 로그) — 경고/에러만 확인하면 됨 |
| 업로드했더니 컴포넌트가 사라짐 | 비파괴 정상 동작 (빌드 시점 합성) |
| AutoClosetObjectToggle에 모르는 컴포넌트가 붙음 | BlendshapeToggle 자동 마이그레이션 — 정상 |

### 5.18 FAQ·용어 사전 (`troubleshooting/faq`)

**FAQ**:
- 옷장을 여러 개 만들 수 있나요? → 네 (옷장 안에 옷장은 불가)
- 의상은 몇 벌까지? → VRChat 제한 맥락 설명(메뉴 한 페이지 8칸, 아바타 전체 파라미터 256bit 중 옷장이 8bit 사용) + 8벌 초과 시 메뉴 동작은 미결사항 ⑤ 실기 확인 후 작성
- 갈아입은 옷이 재접속 후에도 유지되나요? → 네 (saved 파라미터)
- 토글을 안 붙인 부모 오브젝트에도 하이어라키 아이콘이 보여요 → 정상 (자식에 토글이 있음을 알리는 전파 표시) — [사진: 옷장 루트·중간 부모·토글 오브젝트에 아이콘이 표시된 하이어라키]
- 다른 최적화 도구(AAO 등)와 같이 써도 되나요? → misc/optimizers 링크
- 아바타를 업로드하면 무엇이 만들어지나요? → NDMF 생성물 위치 한 줄 + "원본은 안 바뀜"
- 지원하는 Unity/SDK 버전은? → 설치 페이지 링크

**용어 한 줄 사전** (본문 첫 등장 정의의 모음 — 원칙 6): 블렌드셰이프(셰이프키) / Expressions 메뉴 / Expression Parameters / saved 파라미터 / FX / 비파괴(NDMF)

### 5.19 기타 3페이지 (`misc/`)

- **구버전에서 업그레이드** (`upgrade-legacy`): `Hirami > Upgrade Legacy Closet` → "구버전 옷장 감지" 다이얼로그 → "업데이트" — [사진: 다이얼로그]. 레거시 컴포넌트(ClosetToggle/ClosetBlendshape)의 데이터는 **Auto Apply Closet/의상 추가로 ClosetConfig가 붙을 때** 자동 이관됨 (씬을 열 때 자동 동작은 AutoClosetObjectToggle에 BlendshapeToggle이 추가되는 것뿐). 대상 구버전 범위는 미결사항 ⑪ 확인 후 표기
- **최적화 도구와 함께 쓰기** (`optimizers`): AAO TraceAndOptimize / d4rk Avatar Optimizer 사용 시 보존 PhysBone이 자동으로 최적화 제외 등록됨 (v1.0.9). 실패 시 콘솔 경고가 뜬다는 안내
- **릴리스 노트** (`changelog`): 1.0.0→1.0.9 사용자 가시 변경점 타임라인 (조사된 버전 연표 재사용)
